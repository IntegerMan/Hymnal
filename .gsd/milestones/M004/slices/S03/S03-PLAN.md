# S03: Git Toolbar Commit Workflow

**Goal:** Add a Git toolbar commit workflow that appears only for Git-backed workspaces, shows the current branch and uncommitted-change count, stages all changes for Commit only or Commit & Push, refreshes after saves and Git operations, and exposes raw Git stderr through notifications on failure.
**Demo:** Open a Git-backed workspace with uncommitted changes, verify branch and change count appear, use Commit only and Commit & Push paths against a local repo, and verify the count refreshes or stderr appears in a notification.

## Must-Haves

- Must-haves: (1) Own/support R008 by providing stage-all, commit with optional/default message, and push to current remote through system Git on PATH; (2) introduce IGitService, ProcessGitService, and a testable process-runner seam that returns structured success/stdout/stderr without swallowing stderr; (3) add GitPanelViewModel with debounced workspace-root FileSystemWatcher, refresh after EditorViewModel.Saved, and clean disposal; (4) hide the UI when system Git is unavailable or the workspace root is not inside a repository; (5) provide a commit dialog whose default message is exactly `Hymnal: save progress {ISO-8601}` and whose failure path calls INotificationService with raw stderr; (6) verify both fake-runner failure behavior and a real temp local-repo commit/push workflow. Demo: Open a Git-backed workspace with uncommitted changes, see branch and change count in the toolbar, run Commit only, make another change, run Commit & Push against a local remote, and observe refreshed count or raw stderr notification on failure. Threat surface: user-supplied commit messages and workspace paths reach system Git; no secrets should be logged or persisted, but raw Git stderr is intentionally user-visible because it is the diagnostic contract. Requirement impact: advances R008; re-verify S01/S02 editor save paths because Git refresh depends on EditorViewModel.Saved and workspace routing but should not change corkboard/docs behavior. Proof level: operational/integration; real runtime required for local Git integration tests; human/UAT remains recommended for desktop dialog polish but automated ViewModel, service, and smoke tests are the stopping condition. Verification: `dotnet test tests/Hymnal.Core.Tests/Hymnal.Core.Tests.csproj --filter FullyQualifiedName~ProcessGitServiceTests`; `dotnet test tests/Hymnal.Core.Tests/Hymnal.Core.Tests.csproj --filter FullyQualifiedName~GitPanelViewModelTests`; `dotnet test tests/Hymnal.Core.Tests/Hymnal.Core.Tests.csproj --filter FullyQualifiedName~MainWindowGitPanelTests`; `dotnet test tests/Hymnal.Core.Tests/Hymnal.Core.Tests.csproj --filter FullyQualifiedName~ProcessGitServiceLocalRepoTests`; `dotnet build src/Hymnal/Hymnal.csproj`. Observability/diagnostics: runtime signals are GitPanelViewModel.IsVisible, BranchName, UncommittedChangeCount, IsBusy, LastError/notification banner, and raw stderr in GitCommandResult; inspection surfaces are toolbar state, notification banner text, fake-runner call logs in tests, and temp-repo Git history/status in integration tests; redaction constraint is do not surface command-line secrets beyond Git stderr already emitted by system Git. Integration closure: consumes WorkspaceViewModel.WorkspaceRoot/WorkspaceChanged, EditorViewModel.Saved, NotificationService/INotificationService, MainWindow top toolbar, and existing DI in App.axaml.cs; new wiring is IGitService + IProcessRunner + GitPanelViewModel registration plus Commit dialog hookup; after this slice, M004 should be end-to-end usable with nothing intentionally deferred inside the sketch.
